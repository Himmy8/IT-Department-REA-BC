# Быстрый старт участника

## 1. Поймите задачу

Прочитайте [главный README](../README.md), затем найдите назначенную Issue. В задаче должны быть контекст, ожидаемый результат и критерии готовности.

## 2. Получите только нужные доступы

Запросите у руководителя доступы, необходимые именно для вашей задачи. Никогда не просите переслать токен в сообщении. Правила — в документе [Секреты и доступы](secrets-and-access.md).

## 3. Настройте локальное окружение

1. Склонируйте репозиторий.
2. Создайте рабочую ветку от `main`.
3. Скопируйте `.env.example` в `.env`.
4. Получите секреты безопасным способом и заполните только локальный `.env`.
5. Следуйте инструкции в README нужного компонента.

Команды запуска появятся после выбора технологического стека.

## 4. Работайте через Pull Request

Следуйте [GitHub workflow](github-workflow.md). Если задача меняется по ходу работы, сначала обновите Issue — это снижает число недопониманий.

## К кому обращаться

- по приоритету и результату — к руководителю IT;
- по техническому решению — к ответственному за компонент;
- по текстам, кнопкам и визуальному сценарию — к дизайнеру из медиа-отдела через бриф;
- по таблицам и доступам к данным — к владельцу Google Sheets.
