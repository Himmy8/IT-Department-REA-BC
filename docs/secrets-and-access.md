# Секреты и доступы

## Никогда не добавляем в Git

- токен Telegram-бота;
- ключи и JSON-файлы Google Service Account;
- идентификаторы и секреты GigaChat;
- пароли, cookies и приватные ключи;
- выгрузки таблиц с персональными данными.

`.env.example` содержит только названия переменных и безопасные примеры. Настоящие значения хранятся локально в `.env`, а для автоматизации и production — в GitHub Secrets или хранилище секретов хостинга.

## Принцип минимальных прав

- Выдавайте человеку или сервису только необходимый доступ.
- Для Google Sheets используйте отдельный сервисный аккаунт.
- Открывайте сервисному аккаунту только нужную таблицу.
- Не используйте личные учётные данные в production.
- Удаляйте доступ, когда он больше не нужен.

## Если секрет попал в Git или чат

1. Сразу сообщите руководителю IT.
2. Отзовите и перевыпустите секрет — простого удаления из файла недостаточно.
3. Проверьте логи и возможное использование.
4. Очистите историю безопасным согласованным способом.
5. Зафиксируйте причину и меру, предотвращающую повторение.

## Ответственные

Руководитель IT утверждает доступы. Владелец конкретной системы помогает выдать минимально необходимые права и ведёт список активных доступов.
